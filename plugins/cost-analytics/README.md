# 费用分析

图表从左到右为：渠道 Token → 模型 Token → 开销。左侧按提供者渠道汇总，中间按模型 ID 汇总，右侧按“渠道＋模型”显示实际费用；同一模型保持同色。Token 用量为未缓存输入、缓存读取、缓存写入和输出之和。

价格键可以使用 `渠道/模型`，例如 `extralink/glm-5.3-flash` 和 `openlux-glm/glm-5.3-flash` 分别配置。未配置渠道专属价格时会兼容使用同名模型的裸价格；配置了渠道专属价格后优先使用专属价格。完全没有匹配价格的渠道显示“未知”，总费用只包含已配置部分。渠道缺失的历史记录标为 `(unknown)`，不会根据当前配置猜测来源。价格仍在插件的 `prices` 配置或 `cost-analytics` 用户设置中修改。

升级后需重新加载后端插件以从历史日志重建渠道统计；仅刷新浏览器不能保证后端代码重新加载。不需要修改或删除原始会话记录。

所有单价（输入、缓存读取、缓存写入、输出及峰谷单价）均为配置币种的每百万 Token 价格。费用 = 各类 Token 数量 × 对应单价之和 ÷ 1,000,000。修改后历史会话会按当前单价重新计算，无需清除用量记录。

费用弹窗最大宽度为 800 像素，随屏幕宽度收缩并支持纵向滚动。桑基图采用细竖条节点、半透明带状连线和节点内侧标签；渠道列按提供者聚合，模型列按模型 ID 聚合，费用列保留渠道/模型路由，各列按本列真实占比独立缩放，零费用面积为零，未知价格不绘制费用连线。

在 Web 界面汇总会话的请求次数、token 用量和估算费用，提供按项目、会话查看的设置页面。当前会话的费用胶囊与内置 Token 用量胶囊显示在同一行，点击后可查看费用明细。费用弹窗复用内置 Token 用量弹窗的菜单表面、标题分隔线和双列详情布局；其中的渠道 Token→模型 Token→开销流图由随插件打包的 d3-sankey 0.12.3 排版。

依赖宿主 settings、sessionQuery 服务。价格由插件配置和用户设置决定，估算结果不等于供应商账单。插件会读取本机会话历史；不会把这些会话打包到本仓库。大规模会话库的性能和各提供者计价差异需要按实际环境验证。

从仓库根目录运行 `node scripts/install.mjs cost-analytics` 安装。此插件来自本地版本，尚未对所有 Harness 版本做兼容性验证。
