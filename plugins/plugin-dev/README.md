# DSH 插件开发指令

在 DSH 输入框中输入 `/plugin-dev`，把随插件打包的中文开发教程排入当前会话。模型会确认收到教程，等待具体需求。也可以一次输入：

```text
/plugin-dev 为我的插件增加一个通用设置开关
/plugin-dev 检查当前插件为什么没有显示在设置里
```

支持随指令附加图片和文件。模型忙碌时，教程与需求排入后续轮次，不打断当前工作。返回“已排入”表示消息已提交，不代表模型已读完或任务完成。

教程位于 [GUIDE.md](GUIDE.md)，覆盖定位项目、查找接口、Host/Client 分工、设置持久化、斜杠指令、模型输入、安装挂载和测试。只包含 DSH 插件开发内容；源码导航基于本工作区，运行时验证基于 `0.1.5-rc.1`。其他版本应以实际导出和类型声明为准。

## 安装与维护

这是只有 Host 入口的独立插件，不需要浏览器 bundle。把本目录作为 file 依赖安装到使用的 profile，再添加补丁：

```yaml
- insert:
    - id: command-plugin-dev
      name: '@deepseek-ai/dsh-command-plugin-dev'
```

宿主需要 commands 服务及兼容的 Cordis、dsh-llm peerDependencies。部署时确认已安装依赖能够解析。运行 `node --test plugins/plugin-dev/tests/*.spec.js` 验证本地开发目录；测试还需要与宿主同版本的命令、会话和 Loader 依赖。

修改 GUIDE.md 后重新安装插件并重新加载 Host 插件，使启动时读取的教程更新。刷新网页后可在 `/` 菜单查找 `plugin-dev`。已有会话中发送过的教程不自动替换，再次调用会发送新的一份。

## 模型影响与限制

每次调用会发送整份教程，消耗输入 token；长会话压缩后可能需要再次调用。教程通过正常 followup 输入进入模型历史，在 Agent 接纳后记录为用户消息。没有永久系统提示词修改，不保证所有小模型都能完全遵循教程。禁用插件会移除指令，不删除已有会话中的教程。
